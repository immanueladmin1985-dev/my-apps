# PHASE 8 보고서: 그림 파일 연결, 따라잡기 장치

## 그림 파일 연결

- 그림 파일이 있으면 그림을, 없으면 지금처럼 도형을 그립니다. 그림을 넣을 때 코드나 데이터는 고치지 않아도 됩니다 (`scripts/core/art.gd`).
- **영웅·몬스터** (`assets/heroes/<id>.png`, `assets/monsters/<id>.png`): 발밑에 팀 색 고리, 그 위에 그림을 그립니다. 바라보는 방향에 따라 좌우를 뒤집고, 움직이면 살짝 튀고, 공격하면 기울고, 맞으면 붉게 번쩍입니다. 쓰러지면 옆으로 누워 흐려집니다. 체력 막대는 그림 위로 올라갑니다. 용기사가 변신하면 `dragon_knight_dragon.png` 를 씁니다.
- **영웅 얼굴**: 전신 그림의 머리 쪽을 잘라 팀 현황(화면 위), 영웅 선택, 결과 화면의 동그란 칸에 씁니다.
- **아이템** (`assets/items/<id>.png`): 상점, 아이템 칸, 아이템 도감에 씁니다.
- **맵** (`assets/backgrounds/`): 바닥 무늬(`ground_grass`), 벽(`wall_rock`), 기지(`base_fountain`, `ground_dirt`), 상점(`shop`), 중앙 무대(`center_stage`, `ground_stone`), 던전(`camp_ring`, `ground_dungeon`), 보스 자리(`boss_altar`, `ground_lava`, `ground_forest`)를 그립니다. 장식(나무·바위·수정·횃불)은 그림이 있을 때만, 벽·캠프·기지를 피해서 맵마다 같은 자리에 46개까지 흩어 놓습니다. 장식은 부딪히지 않습니다.
- **정리 도구** `tools/import_art.py <그림 폴더>`: 파일 이름으로 자리를 찾고, 마젠타 배경을 지우고, 투명 여백을 자르고, 크기를 줄여서(캐릭터 384px, 아이템 128px, 맵 512px) 저장합니다. 이름이 맞지 않는 파일과 아직 없는 그림을 알려 줍니다.
- 요청 프롬프트와 파일 이름: `docs/ART_PROMPTS.md`.
- 확인 방법: 도형으로 만든 가짜 그림 77장을 작업 폴더 복사본에 넣고 전투·전체 맵·상점·영웅 선택 화면을 캡처했습니다 (`docs/phase8/art_test_*.png`). 가짜 그림은 저장소에 넣지 않았습니다.

## 따라잡기 (킬 점수가 뒤진 팀)

| 킬 차이 | 시간당 골드·처치 골드 | 부활 시간 |
|---|---|---|
| 1 | +8% | −6% |
| 3 | +24% | −18% |
| 5 | +40% | −30% |
| 7 이상 | +50% (최대) | −40% (최대) |

- 값은 `data/config/progression.tres` 의 `comeback_*` 항목입니다.
- 뒤진 팀의 화면 위쪽 시간 옆에 "역전 보너스 골드 +n% 부활 −n%" 가 나옵니다.
- 기존의 현상금(연속 처치 중인 영웅 처치)과 따라잡기 경험치(레벨이 낮은 팀)는 그대로 둡니다.

## 밸런스 측정 (120판씩)

| 측정 | 일방적인 경기 (진 팀 3킬 이하) | 승률 범위 |
|---|---|---|
| PHASE 7 끝 | 44판 | 40~60% |
| 따라잡기 추가 | 35판 | 28% (성녀) ~ 71% (용기사) |
| 성녀·용기사 조정 후 | 40판 | 34% (엘프 궁수) ~ 63% (용기사) |

- 조정: 용기사 공격력 60→58, 변신 시간 12/14/16→10/12/14초. 성녀 주문력 35→42, W 치유 150~360→170~395.
- **측정 오차가 큽니다.** 엘프 궁수는 수치를 바꾸지 않았는데 49% 에서 34% 로 바뀌었습니다. 한 가지를 바꾸면 모든 경기의 흐름이 달라지기 때문에, 영웅마다 약 70판으로는 ±10% 정도가 오차 안에 들어갑니다. 그래서 이번에는 더 맞추지 않았습니다.
- 일방적인 경기는 44판에서 35·40판으로 줄었지만, 이 차이도 오차와 비슷한 크기입니다. 더 정확히 보려면 판 수를 크게 늘려야 합니다(예: 600판, 약 2시간).
- 측정 결과: `docs/phase8/balance_comeback.txt`, `balance_final.txt`. 스크립트 오류는 모두 0개였습니다.
