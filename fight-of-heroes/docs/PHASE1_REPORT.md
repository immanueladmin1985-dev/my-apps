# PHASE 0·1 완료 보고

## 구현한 기능

| 구분 | 내용 |
|---|---|
| 프로젝트 | Godot 4.7.2, Compatibility 렌더러, 1280×720 기준·가로 고정·몰입형 전체화면·화면 꺼짐 방지, 한글 글꼴 |
| 기반 | EventBus, DataRegistry(내보낸 APK 의 `.remap` 처리 포함), SaveManager(JSON, 버전 정보), GameManager |
| 전투 핵심 | Unit + 컴포넌트(능력치·체력·마나·상태 효과·기본 공격), CombatManager 피해 파이프라인(치명타 → 관통 → 방어 감소 → 보호막 → 체력 → 사망) |
| 스킬 | SkillData + 효과 조합(피해, 회복, 보호막, 상태 효과, 범위·지연 범위·지속 범위, 직선·관통 투사체, 돌진), 시전 검사(단계·쿨타임·마나·기절·사거리) |
| 상태 효과 | 기절, 둔화, 가속, 지속 피해, 능력치 버프 (가장 강한 둔화·가속 하나만 적용) |
| 영웅 | 검성(돌진 베기, 회전베기, 검기 방어, 일섬), 엘프 궁수(관통 화살, 가시 덫, 후퇴 도약, 화살비) |
| AI | 상태 머신(IDLE, MOVE, CHASE, ATTACK, RETREAT, DEAD, RESPAWN), 난이도 3단계(반응 간격·스킬 사용 확률·조준 오차·후퇴 판단), 스킬 용도별 판단, 길찾기, 끼임 풀기 |
| 조작 | 떠오르는 조이스틱, 공격 버튼(가까운 적 자동 선택), Q/W/E/R(누르기 = 자동 조준, 끌기 = 조준선·범위 표시, 취소 영역), 적 누르기로 대상 선택, 멀티 터치 |
| 화면 | 점수·시간·일시정지, 체력·마나 막대(보호막 표시), 머리 위 체력바, 피해 숫자, 쿨타임·마나 부족 표시, 카메라 추적, 결과 창 |
| 경기 규칙 | 사망·부활(4초 + 레벨 × 1.5초), 우물 회복, 팀 킬 점수와 목표 킬 승리 |
| 빌드 | GitHub Actions 에서 시험 → 서명 전 APK → `fight-of-heroes-build` 브랜치. 서명 키는 Artifact 에 보관 |

## 테스트 결과

- 자동 시험 39개 모두 통과, 스크립트 오류 0개 (`docs/phase1/test_result.txt`). GitHub Actions 에서도 같은 시험을 통과했습니다.
- 1대1 시뮬레이션(게임 시간 180초 × 2판): 양쪽 영웅이 Q/W/E/R 를 모두 썼고, 사망과 부활이 일어났으며, 최대 끼임 시간은 0.52초였습니다(기준 2초).
- 내보낸 패키지에서 데이터 18개 파일을 오류 없이 불러오는 것을 확인했습니다.
- 화면 캡처: `docs/phase1/` 의 20:9, 16:9, 4:3. 버튼이 겹치거나 화면 밖으로 나가지 않습니다.

## 확인하지 못한 것 (실제 기기 필요)

- 휴대폰에 설치·실행, 실제 손가락 멀티 터치, 기기에서의 FPS, 노치 화면의 안전 영역 여백.
- 작업 환경은 그래픽 카드 없이 CPU 로 그리기 때문에 캡처의 FPS(15~23)는 기기 성능과 관계가 없습니다.

## 알려진 문제와 남은 작업

- 1대1 보통 난이도에서는 180초에 1킬 정도로 처치가 적습니다. AI 의 후퇴·우물 회복이 강한 편이라 PHASE 2 에서 3대3 과 함께 조정합니다.
- 맵 중앙 장애물은 PHASE 3 에서 최종 보스 자리로 바꿉니다.
- 패시브, 레벨업, 스킬 포인트, 몬스터, 아이템은 다음 PHASE 에서 만듭니다.
- 임시 그림(도형)을 쓰고 있습니다. 실제 스프라이트가 생기면 `sprite_frames` 로 연결합니다.

## PHASE 2 에서 할 일

아군 AI 2명·적군 AI 3명, FOLLOW 상태와 아군 지원, 팀 집중 공격(어려움), 도움 처리, 3대3 시뮬레이션 시험.
