# DICEBOUND · 운명의 주사위

주사위 5개를 굴리고, 마음에 들지 않는 주사위만 골라 다시 굴려 족보를 완성하는 다크 판타지 로그라이크입니다. 주인공 4명(히든 2명 별도) 중 하나를 골라 출발 지점에서 분기형 맵을 따라 10층을 지나면 최종 보스(6종 중 하나)가 기다립니다.

- 주소: https://immanueladmin1985-dev.github.io/my-apps/dicebound/
- 빌드 과정이 없습니다. 브라우저에서 `index.html`을 열면 바로 실행됩니다.

## 실행

```bash
# 저장소 루트에서
python3 -m http.server 8000
# 브라우저에서 http://localhost:8000/dicebound/ 접속
```

`file://`로 직접 열어도 게임은 동작하지만, 서비스 워커(오프라인 실행)와 홈 화면 설치는 `http(s)://` 주소에서만 동작합니다.

## GitHub Pages 배포

1. 변경 사항을 `main` 브랜치에 병합합니다.
2. 저장소 Settings → Pages에서 Source가 `main` 브랜치 `/ (root)`인지 확인합니다. (이미 다른 앱이 이 설정으로 배포되고 있습니다.)
3. 몇 분 뒤 위 주소에서 확인합니다.
4. 파일을 추가하거나 바꾼 경우 서비스 워커 캐시를 새로 만듭니다: `python3 dicebound/tools/make_sw.py v2` (버전 문자열을 올립니다).

## 주인공

| 주인공 | 체력 | 시작 주사위 | 고유 능력 | 공격 연출 |
| --- | --- | --- | --- | --- |
| 기사 | 56 | 강철 주사위 | 전투 시작 시 방어 8 | 베기 |
| 사냥꾼 | 50 | 빙결 주사위 | 공격할 때 늑대가 함께 물어 피해 +3 | 불화살 투사체 + 충격 |
| 궁수 | 46 | 피의 주사위 | 매 턴 재굴림 +1, 적에게 출혈을 줄 때 +2 | 화살 투사체 + 충격 |
| 마법사 | 48 | 불꽃 주사위 | 회복 효과 +2, 원 페어 이상으로 공격하면 적에게 화상 1 | 마력탄 투사체 + 폭발 |
| 비치발리볼 (히든) | 50 | 생명 주사위 | 매 턴 재굴림 +1, 스트레이트 공격 피해 +8 | 배구공 투사체 + 충격 |
| 격투가 (히든) | 60 | 저주 주사위 | 체력이 절반 이하이면 공격 피해 +5 | 주먹 + 충격 |

- 히든 캐릭터: 메인 메뉴의 로고를 1.5초 안에 이어서 다섯 번 누르면 비치발리볼 일러스트와 함께 "숨겨진 주인공" 선택 화면이 열립니다. 해금 상태는 저장하지 않으므로 매번 다섯 번 눌러야 합니다. 도감의 주인공 목록에는 한 번이라도 플레이한 히든 캐릭터만 보입니다.
- 비치발리볼 일러스트는 히든 캐릭터를 찾았을 때, 비치발리볼로 여정을 시작할 때(로딩 화면처럼 2.6초), 비치발리볼로 승리했을 때 화면 가득 뜹니다. 세로 화면에서는 세로 그림 2장 중 하나, 가로 화면에서는 가로 그림을 씁니다. 화면을 누르면 닫힙니다.
- 예전 주인공 4명(드루이드·궁수·기사·전사)은 적(타락한 드루이드·엘프 사냥꾼·검은 숲의 검사·방패 투사)이 되었습니다. 예전 주인공으로 진행하던 여정은 이어하기에 나오지 않습니다.

## 캐릭터 방향과 관절 움직임 (`js/rig.js`)

- 적 그림이 오른쪽을 보고 있으면 `data.js` 의 적 정의에 `flip: true` 를 적어 좌우로 뒤집습니다. 지금은 고블린 궁수, 해골 궁수, 세이렌 예언자, 하피 여왕, 드라이더 여왕이 해당합니다.
- 한 장짜리 그림을 WebGL 격자(32×44칸)에 입히고 격자 꼭짓점을 관절별로 옮겨서 그립니다. 그림을 조각내지 않으므로 이음매가 생기지 않습니다.
- 관절 위치는 그림의 투명도를 읽어 자동으로 정합니다. 머리 꼭대기와 몸 중심선을 찾고 목·어깨·가슴·허리를 사람 비율로 나눈 뒤, 줄마다 몸통 폭을 재서 몸에서 떨어진 팔·무기만 어깨를 따라 돌게 합니다. 땅에 짚은 칼이나 지팡이는 허리를 따라 곧게 움직입니다.
- 움직임 종류: 사람형(`human`), 네발 짐승(`beast`, 늑대), 슬라임(`blob`), 다리가 많은 것(`crawler`, 거미·드라이더). 적이나 주인공 정의에 `rig: { kind, arms, still, float }` 로 바꿉니다. `arms` 는 팔 움직임 크기(손이 몸에 붙은 그림은 작게), `still` 은 움직이지 않을 영역(사냥꾼 옆 늑대)입니다.
- 동작: 등장, 대기(숨쉬기·흔들림, 은은하게), 공격(뒤로 젖혔다가 휘두르기), 마법·활(팔 들기), 피격, 버프, 쓰러짐(크게). 원거리 행동을 하는 적과 사냥꾼·궁수·마법사·비치발리볼은 공격할 때 마법·활 동작을 씁니다.
- WebGL 을 쓸 수 없거나 `file://` 로 연 경우에는 원래 그림과 CSS 움직임으로 돌아갑니다. 설정의 "연출 줄이기"나 기기의 움직임 줄이기를 켜면 관절 움직임도 멈춥니다.

## 전투 규칙

- 내 차례가 시작되면 주사위 5개가 자동으로 굴러갑니다.
- 다시 굴릴 주사위를 눌러 고른 뒤 `재굴림`을 누릅니다. 고르지 않은 주사위는 그대로 남습니다. 재굴림은 턴마다 2번입니다(궁수·비치발리볼·시간의 홀 +1, 재굴림 두루마리 +2).
- `공격`을 누르면 가장 강한 족보 하나의 효과가 적용되고, 적이 살아 있으면 예고한 행동을 합니다.

| 족보 | 효과 |
| --- | --- |
| 파이브 오브 어 카인드 | 공격 (눈 합×2+10), 방어 10, 회복 10 |
| 포카드 | 공격 (네 눈 합×1.5+6), 적에게 빙결 2 |
| 풀하우스 | 공격 (다섯 눈 합+4), 회복 6 |
| 스트레이트 (1~5, 2~6) | 공격 16 (2~6은 18), 방어 8 |
| 트리플 | 공격 (세 눈 합+8), 적에게 출혈 2 |
| 투 페어 | 공격 (네 눈 합+2), 방어 5 |
| 원 페어 | 공격 (두 눈 합+4) |
| 하이 카드 | 공격 (가장 높은 눈+2), 방어 3 |

상태 효과는 플레이어와 적에게 같은 규칙으로 적용됩니다.

| 상태 | 규칙 |
| --- | --- |
| 방어 | 받는 피해를 먼저 막습니다. 자기 차례가 다시 오면 사라집니다. |
| 출혈 | 자기 차례가 시작될 때 중첩만큼 피해(방어 무시), 중첩 -1 |
| 화상 | 자기 차례가 시작될 때 피해 3(방어 무시), 남은 턴 -1 |
| 빙결 | 공격 피해 ×0.7, 공격할 때마다 중첩 -1 |
| 힘 | 공격 피해 +중첩 (전투 동안 유지) |

공격 효과 계산 순서(`js/rules.js`의 `computeAttack`): 족보 기본 효과 → 특수 주사위 → 유물 고정 보너스 → 힘 → 왕의 왕관(×1.25) → 빙결(×0.7) → 상태 부여 보너스. 화면의 예상 피해와 실제 공격은 같은 함수를 사용하므로 서로 다르게 계산되지 않습니다.

중복 적용 방지: 전투 행동(`attack`)은 상태를 한 번에 끝까지 계산하고 연출 목록만 남깁니다. 화면은 그 목록을 재생할 뿐 상태를 바꾸지 않습니다. 보상·구매·이벤트 선택은 각각 `받음/판매 완료/완료` 표시를 확인한 뒤에만 적용되고, 특수 주사위 구매는 교체할 칸을 고른 순간에 한 번만 결제됩니다.

## 파일 구조

```
dicebound/
  index.html            화면 틀과 스크립트 연결
  css/style.css         전체 스타일 (휴대폰 세로 기준, 가로·태블릿·PC 대응)
  js/util.js            네임스페이스, 시드 난수, localStorage 래퍼
  js/data.js            족보·주사위·유물·소모품·적·NPC·업적 정의와 이미지 경로
  js/rules.js           순수 함수: 족보 판정, 공격 계산, 적 피해, 맵 생성·검증
  js/game.js            여정 상태와 모든 행동(맵 이동, 전투, 보상, 상점, 휴식, 이벤트, 저장, 도감·업적)
  js/rig.js             관절 움직임: 캐릭터 그림을 WebGL 격자로 휘어 그린다
  js/ui.js              화면 그리기, 연출 재생, 모달, 정보창
  js/pwa.js             홈 화면 설치, 전체화면, 화면 꺼짐 방지
  js/main.js            시작
  assets/               이미지 시트에서 잘라 낸 리소스 (아래 표)
  manifest.webmanifest, sw.js, icon-*.png   홈 화면 설치·오프라인
  tests/                단위 테스트, 밸런스 시뮬레이션, 브라우저 점검
  tools/                시트 자르기, 서비스 워커 캐시 목록 생성
```

| 폴더 | 내용 | 원본 시트 |
| --- | --- | --- |

시트에 들어 있던 글자(이름표, 설명, 제목)는 잘라 낼 때 모두 제외했습니다. 리소스를 다시 만들려면 원본 시트 세 장을 준비해서 다음을 실행합니다.

```bash
pip install pillow numpy
python3 dicebound/tools/cut_sheets.py <UI·아이콘 시트(마젠타 배경)> <캐릭터 시트> <배경·UI 시트> dicebound/assets
pip install scipy
sh dicebound/tools/cut_sheets2.sh <두 번째 묶음 시트 폴더> dicebound/assets   # 주인공·몬스터·배경·이펙트 (필요한 파일 이름은 스크립트 첫머리 참고)
```

새 몬스터 시트(고블린·산적·해골·늑대·거미·슬라임 13종)와 새 주인공 시트는 따로 자릅니다.

```bash
python3 dicebound/tools/cut_mobs2.py <monsters-new.png> dicebound/assets/mobs
python3 dicebound/tools/cut_heroes2.py <새 주인공 시트 폴더> dicebound/assets   # 필요한 파일 이름은 스크립트 첫머리 참고
```

고해상도 원본이 생기면 `assets/` 안의 같은 파일 이름으로 바꿔 넣기만 하면 됩니다(배경·초상은 `jpg`, 투명 이미지는 `webp`).

## 저장

- 진행 중인 여정, 도감·업적·통계, 설정을 기기의 `localStorage`에 저장합니다(`dicebound.run.v1`(내용은 v2 형식), `dicebound.meta.v1`, `dicebound.settings.v1`).
- 모든 행동이 끝날 때마다 저장하므로, 창을 닫았다가 다시 열면 메인 메뉴의 `이어하기`로 같은 상태에서 계속할 수 있습니다.

## 아직 구현하지 않은 것

- 사운드와 배경 음악은 없습니다.
- 시트의 작은 픽셀 스프라이트(걷기·전투 동작 프레임), 배경 소품, 우편·공유 버튼, 회색 바탕 "캐릭터 & 몬스터 애셋 모음" 시트, 대형 이펙트 시트(검기·연기 등)는 사용하지 않았습니다. 전투 연출은 돌진·흔들림·투사체·이펙트 이미지로 표현합니다.
- 처음 시트의 보스 4종과 초상 몬스터 5종은 전신 그림이 없어 초상의 가장자리를 흐리게 처리해 무대에 놓았습니다. 전신 그림이 생기면 `assets/mobs`처럼 바꿀 수 있습니다.
- 이전 버전(v1)에서 저장한 진행 중인 여정은 이어할 수 없습니다(도감·업적·설정은 유지됩니다).
- 이미지 시트가 1536×1024 크기여서 잘라 낸 배경과 초상은 해상도가 낮습니다. 화면에서는 흐림과 어두운 그라데이션으로 보완했습니다.
- 밸런스는 단순한 봇(전체 승률 약 60%, 주인공별 54~66%) 기준으로만 맞췄고, 사람이 직접 플레이한 테스트는 하지 않았습니다.
- 여정은 1막(10층 + 보스)뿐이며, 난이도 선택은 없습니다.
